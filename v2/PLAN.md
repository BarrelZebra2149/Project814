## 0. 한 줄 요약
점수가 무너지는 이유는 "그 칸에만 의존하는 수(급소)" 때문이고, 이것은 **정확히 계산할 수 있다.**
그래서 탐색은 **구멍 개수(매끄러운 값)를 에너지로 어닐링**하고 (K는 기록용), 급소를 줄이고 자유 칸을 늘리는 보조 항을 둔다.
이동은 **이미 3칸이 맞아 있는 체인(겹치는 숫자)을 찾아 1칸만 바꿔 대체 체인을 만드는 것**을 중심으로 한다.
(측정 근거: 고득점 격자는 K 기준으로 칸 2개 변경까지 완전히 막혀 있지만, 구멍 개수는 칸 하나에 중앙값 +13~+29로 움직일 수 있다. 2.3)

## 1. 사용자의 통찰과 정식 정의

사용자 설명: "이미 이 숫자를 읽을 수 있는 체인이 여러 개 있으면 하나 없어져도 괜찮지만, 그거 하나 없애면 터지는 숫자가
반드시 존재한다. 그걸 최소화하는 게 중요하다. 숫자 하나 바꾸면 여러 체인이 박살나고, 이를 채울 대안을 찾기 위해
겹치는 숫자를 찾는 것이 핵심이다."

정의 (모든 구현은 이 용어를 쓴다):

| 용어 | 정의 |
|---|---|
| 체인 | 칸들의 순서열 (길이 1~4, 킹 이동, 같은 칸 재방문 허용). 읽은 숫자열이 수 n이면 "n의 체인". 첫 숫자 0이면 수가 아님 |
| `cnt[n]` | n의 체인 개수 (방향 있는 걷기 기준. 뒤집은 걷기는 rev(n)의 체인으로 따로 셈) |
| `cntx[n][x]` | n의 체인 중 칸 x를 지나는 것의 개수 (한 체인이 x를 두 번 지나도 1) |
| **급소 칸** | `cnt[n] > 0` 이고 `cntx[n][x] == cnt[n]` 인 칸 x. 즉 n의 **모든 체인이 x를 지난다** |
| **급소 수 (SPF)** | 급소 칸이 하나라도 있는 수. 그 칸 하나 바뀌면 n이 사라진다 |
| `crit[x]` | 칸 x를 바꾸면 사라지는 수 중 **가장 작은 수** (K 이하만). 없으면 `∞` |
| **자유 칸** | `crit[x] = ∞` (= 바꿔도 K 이하의 수가 하나도 안 사라짐) |
| **하중 칸** | `crit[x] ≤ K` |
| 겹침(불일치 1 체인) | 어떤 칸 순서열이 n의 숫자와 **한 칸만 다르고 나머지는 이미 맞는** 것. 그 한 칸만 바꾸면 n의 새 체인이 생긴다 |

칸 x를 숫자 d'로 바꾸면 새 점수는 `min(crit[x], 첫 구멍) − 1`이 되는데, 단 **d'가 만든 새 체인이 그 수를 살리면 예외**다.

## 3. 설계 원리
1. **정확한 계산이 먼저, 학습은 그다음.** 2.1에서 단일 칸 변경의 결과는 97.9%가 공식으로, 나머지도 새 체인 확인으로 **정확히** 계산된다. 단일 변경에는 ML을 쓰지 않는다.
2. **목표 순서:** K를 지킨다 → 첫 구멍을 메운다 → 급소를 줄인다 → 자유 칸을 늘린다.
3. **이동은 "겹침"에서 나온다.** 새 체인은 이미 3칸(4자리 기준)이 맞아 있는 칸 순서열의 나머지 1칸을 바꿔 만든다. 이 1칸은 **자유 칸이거나, 그 칸이 터뜨리는 수를 다른 겹침으로 즉시 살릴 수 있어야** 한다.

## 4. 자료 구조 (`engine.py`, numba)

### 4.1 체인 목록 (격자 숫자와 무관, 한 번만 만든다)
- 길이 L=1..4의 모든 방향 있는 걷기. 8×14에서 L=4는 **40,440개**. 배열 `WALKS[L]` (개수 × L, 칸 번호 0..111).
- 칸별 역색인 `THROUGH[x]` = x를 지나는 (L, 걷기 번호) 목록. L=4 기준 칸당 평균 약 1,400개.

### 4.2 상태
| 이름 | 모양 | 의미 |
|---|---|---|
| `grid` | 112 | 숫자 |
| `cnt` | 10000 (int32) | 1.2절 정의. 0번은 안 씀 |
| `cntx` | 10000 × 112 (int16, 약 2.2MB) | 1.2절 정의 |
| `cutcount[n]` | 10000 | n의 급소 칸 개수 (0이면 튼튼) |
| `crit[x]` | 112 | 1.2절 정의 |
| `K`, `holes` | | 첫 구멍 − 1, 목표 구간의 구멍 집합 |

### 4.3 증분 갱신 (칸 x를 d → d')
1. `THROUGH[x]`의 모든 걷기에 대해, **옛 숫자열**의 수 n에서 `cnt[n] -= 1`, 걷기의 서로 다른 칸 y마다 `cntx[n][y] -= 1`.
2. `grid[x] = d'`.
3. 같은 걷기들의 **새 숫자열** m에서 `cnt[m] += 1`, `cntx[m][y] += 1`.
4. 1·3에서 건드린 수(약 수천 개)만 `cutcount`를 다시 센다. 급소 칸은 그 수의 아무 체인 하나 위에만 있을 수 있으므로,
   **건드린 걷기에서 그 수의 체인 하나를 기억해 두고 그 칸 ≤4개만 확인**한다 (112칸 전체를 훑지 않는다).
   그 수의 체인이 이번 이동에서 하나도 안 보였으면 112칸을 훑는다 (드묾).
5. `crit`은 칸별로 "그 칸이 급소인 수들"의 최솟값이다. 칸별 비트셋(112 × 10000비트)을 두고 최솟값을 다시 구한다.
6. `K`: 사라진 수가 K 이하이면 K를 낮추고, 첫 구멍이 메워졌으면 위로 다시 훑는다.

### 4.4 정확성 테스트 (반드시 통과)
- T1: 임의 격자 1,000개에서 `engine` 전체 계산 결과(`cnt`, `K`)가 `core814.evaluate`와 **전부 일치**.
- T2: 임의 변경 10만 번을 증분으로 적용한 뒤 상태 전체를 처음부터 다시 계산한 값과 **비트 단위 일치** (`cnt`, `cntx`, `cutcount`, `crit`, `K`).
- T3: 2.1의 결과 재현 (예측 K' = 실제 K'인 비율 ≈ 97.9%, 틀림 0).
- 속도: 초당 증분 이동 수를 측정해 `reports/speed.md`에 기록. **추측하지 말고 잰다.**

## 5. 평가 기준 (에너지)

**역할을 둘로 나눈다 (2.3의 결론):**
- **탐색(어닐링) 에너지 `E`** = 구멍 개수 중심의 매끄러운 값. 이동의 수락 여부는 `E`로 정한다.
- **기록(최고점) 판정** = K. `out/best.txt`는 항상 K가 가장 큰 격자다. K는 `E`로 탐색하는 동안 계산해서 기록만 한다.

### 5.1 어닐링 에너지 `E` (주)
`E = H + b·F/K + c·(112 − 자유칸)`, 수락 확률 `exp(−ΔE / T_온도)`.
- **`H` = 구멍 개수** = `Σ_{n=1..T} [cnt[n] == 0]` , **`T = 9999` 고정** (기본).
  - 이유: 2.3에서 이 값이 K보다 훨씬 매끄럽다. 고정 `T`는 목표가 움직이지 않아 에너지 비교가 일관된다.
  - 변형(A/B 팔로 비교): `T = K + 1500` (적응형), 작은 수에 더 큰 가중 `w(n) = 1 + 2·(1 − n/T)`.
  - `H = 0`이면 1~9999 전부 가능 = K ≥ 9999. 그 위(5자리)는 `T` 밖이라 이 단계의 목표가 아니다 (13장 Q5).
- 온도 `T_온도`의 규모는 2.3 기준으로 **구멍 개수 10~30 단위**다 (칸 하나 변경의 중앙값 +13~+29). 시작 온도 약 15, 정체 시 올린다 (8장). 추측이므로 A/B에서 조정.
- `b·F/K`, `c·(112−자유칸)`은 **보조 항**이다. 기본 `b = 5`, `c = 0.5` (추측). A/B 팔 B2에서 켜고 끈다.

### 5.2 사전식 기준 (동점 처리, 기록 갱신용)
앞 항목이 같을 때만 다음을 본다.

1. **K** (클수록 좋다)
2. **첫 구멍 위 구간의 구멍 수**: `(K, K+W]`에서 체인이 없는 수의 개수 (적을수록 좋다). 기본 `W = 400` (`core814`의 look과 같은 창)
3. **급소 위험** `F = Σ(1 ≤ n ≤ K) w(n)`, `w(n) = (1 + β·[n이 급소 수]) / cnt[n]^p` (작을수록 좋다).
   - **합산 범위는 현재 점수 K 이하의 수뿐이다** (사용자 확인). 이미 읽을 수 있어서 **잃을 수 있는 수**들이기 때문이다.
     K보다 위의 수는 F에 넣지 않는다 (구멍이면 2번 항이, 아직 목표 밖이면 무시).
   - **그 수를 읽는 체인이 적을수록 무겁게** 센다 (사용자 결정, 13장 Q3). 급소가 아니어도 체인이 1~2개뿐인 수는 곧 급소가 되므로 미리 압력을 준다.
   - K가 오르면 합산 범위도 넓어져 F가 커진다. 그래서 어닐링 가중합에서는 `F / K`로 정규화해 비교한다.
   - 기본 `p = 1`, `β = 3` (추측, 9장 A/B로 조정)
4. **자유 칸 수** (많을수록 좋다)

(옛 초안의 `−1000·K` 항은 **뺐다.** 2.3에서 K가 절벽이라 어닐링 에너지로 부적합함이 확인됐다.)

## 6. 이동 (`moves.py`)

모든 이동의 결과는 4장 엔진으로 **정확히** 계산한다. 이동은 실제로 적용해 보고, 받아들이지 않으면 되돌린다.

| 이동 | 하는 일 | 사용자 통찰과의 연결 |
|---|---|---|
| **M1 이익 지도 스캔** | 112칸 × 9숫자 = 1008개 단일 변경 전부의 결과를 계산해 가장 좋은 것(또는 어닐링 표본)을 고른다. 급소 칸은 `crit`으로 즉시 걸러지므로 대부분 계산 없이 탈락 | "어느 숫자를 바꿔야 이득인가"를 **정확히** 계산 |
| **M2 보강** | 급소 수 n 하나를 고른다(작은 n 우선). n의 급소 칸 x를 **지나지 않는** 불일치 1 체인을 모두 찾고, 그 1칸 y를 바꿔 n에 대체 체인을 만든다. y는 자유 칸이거나 `crit[y]`가 큰 칸 우선 | "체인 하나 없어져도 괜찮도록" 겹침을 줄임 |
| **M3 연장** | 첫 구멍 K+1에 대해 불일치 1 체인을 모두 찾고, 바꿀 1칸이 자유 칸인 것부터 시도 | 겹치는 숫자를 이용해 K를 올림 |
| **M4 파괴 후 수리** | 하중 칸 x를 바꿔(새 체인을 만들려고) 수 몇 개가 사라지면, 사라진 수 각각에 대해 M3 방식으로 **불일치 1 체인 수리**를 **최대 3~5칸까지** 연달아 시도하고, **묶음 전체**의 `E`로 받아들이거나 전부 되돌린다 | "숫자 하나 바꿔서 여러 체인이 박살나면 대안을 찾기 위해 겹치는 숫자를 찾는다" |

> **M4 수리 깊이에 대한 주의 (2.3):** 고득점 격자에서 칸 2개 조합(1칸 파괴 + 1칸 수리) 50만 가지 중 K를 유지하는 것이 0~1개뿐이었다.
> 따라서 수리 깊이 2에서는 성공이 거의 없을 것으로 예상한다. 깊이 3~5를 시도하고, 성공률을 **깊이별로 기록**해 A/B에서 깊이를 정한다.
> 수락은 K가 아니라 `E`(구멍 개수)로 하므로, K가 잠깐 내려가는 이동도 구멍이 적게 늘면 받아들인다.

- 불일치 1 체인 찾기: 4자리 수 n에 대해 `WALKS[4]` 40,440개를 훑어 숫자 불일치가 정확히 1인 걷기를 모은다 (n당 약 16만 번 비교, numba로 1ms 안팎 예상 — 측정 필요). 길이 2~3도 같은 방식.
- 이동 선택 비율은 context-window(최근 2만 회에 각 이동이 E를 줄인 비율, 최소 10%)로 정한다.

## 7. 학습 (ML) — "어느 숫자를 바꿔야 이득인가"
- **단일 칸 변경:** 6장 M1이 1008개를 **정확히** 계산하므로 ML이 필요 없다. 이것이 사용자 요청("어느 숫자를 바꿔야 이득인가")의 정확한 답이다.
- **ML이 의미 있는 곳:** M4의 **첫 칸 선택**. 하중 칸 x를 바꾼 뒤 수리가 성공할지는 연달아 2~3칸을 탐색해야 알 수 있어 비싸다.
  분류기는 "이 (x, d')로 시작하면 M4 수리가 성공할 확률"을 예측해 후보를 먼저 거른다.
  - 특징: x 주변 5×5 숫자, `crit[x]`, x가 급소인 수의 개수와 자릿수, 그 수들의 불일치 1 체인 개수, 자유 칸까지의 거리.
  - 라벨: M4를 실제로 실행한 결과(성공/실패). 탐색 중 자동으로 쌓인다.
  - 게이트: **고정 기준을 두지 않는다** (사용자 결정, 13장 Q4). 실제로 돌리면서 ML 팔과 비교 팔의 같은 시간당 개선을 계속 기록하고,
    `reports/ml_live.md`에 정리해 사용자와 함께 판단한다. 참고 지표로 궤적 단위 분할 홀드아웃 AUC도 함께 기록한다.
- ML은 9장 A/B의 마지막 팔(B5)로만 들어간다.

## 8. 그대로 유지하는 것 (v1·v2에서)
- **섬 10개**: 섬 0~4는 전부 0 격자 출발, 섬 5~9는 시드 `base_seed+i` 랜덤 격자 출발. 섬끼리 섞지 않는다. 전역 최고 → `out/best.txt`.
  전부 0 격자는 K=0이다. 첫 단계에서 M3(연장)이 1, 2, 3...을 차례로 만들어 간다.
- **중복 확인**: 이미지 코드 = 4대칭 변형 중 사전순 최소의 `blake2b-128`. 섬 최고점 50% 이상 격자만 SQLite 영구 저장, 최근 창 200만 개.
- **정체 탈출 (섬별)**: 정체 = 그 섬의 **`E` 최솟값(구멍 개수)이 `S` 이동(기본 2,000만) 동안 줄지 않음**.
  1차 어닐링 온도↑, 2차 M4 비율↑와 수리 깊이 3→5, 3차 섬 재시작(같은 출발 종류, 새 시드, 최고 격자는 `state/islands/retired.txt`). `--island-restart` 기본 켬.
- **장기 실행**: 워커 7개가 섬 10개를 돌아가며 맡음, 5분마다 원자적 체크포인트, SIGTERM 저장, 자동 재개, `systemd --user`, 결과는 서버에만.
- **상황 표시**: 한 줄 `\r` + `state/status.json`(10초) + `state/progress.csv`(1분).
  `[814] best=K (섬3) | 급소 1234 | 자유칸 5 | 구멍(K..K+400) 37 | ..k/s | 0출발 [...] | 랜덤 [...] | stall [...] | 5d 03:12`
  (참고: 원본은 `tqdm` 막대, `sa814`는 `[sa814] iter=... best=...` 로그 한 줄 + `progress.csv`였다.)

폐기: 줄 라이브러리·줄 조립(2.2 F), 격자 단위 ML(2.2 C), K만 보는 무작위 칸 변경(2.2 E/H).

## 9. A/B 하니스 (설계를 숫자로 정함)
한 팔 = **10개 시드 × 같은 벽시계 시간**(기본 30분, 워커 1개씩), 지표 = 최종 K의 중앙값·최댓값. 같은 평가 수가 아니라 **같은 시간**으로 비교한다(이동마다 비용이 다르므로).

| 팔 | 내용 |
|---|---|
| B0 | 기준: `gen_data.py` 방식 (K×1000+look 언덕 오르기) |
| B1 | 엔진 + **구멍 개수 `E`(T=9999 고정)** + M1 어닐링 |
| B1b | B1에서 `T = K + 1500`(적응형)과 작은 수 가중 변형을 각각 비교 |
| B2 | B1 + 급소 위험 F·자유 칸 (보조 항 켬) |
| B3 | B2 + M2 보강 + M3 연장 |
| B4 | B3 + M4 파괴 후 수리 |
| B5 | B4 + ML 첫 칸 선택 (7장 게이트 통과 시) |

- 채택: 앞 팔보다 중앙값이 높고 Mann-Whitney p<0.05면 다음 팔을 기준으로 삼는다. 높아지지 않는 구성 요소는 빼고 보고한다.
- 각 팔에서 K 구간별로 급소 비율·자유 칸 수를 기록해 2.1과 비교한다 (높은 K에서 자유 칸이 사라지는지 확인).
- **B1~B4가 모두 B0 이하이면 구현을 멈추고 사용자에게 보고한다.**

## 11. 위험
- 증분 갱신(4.3)의 `cutcount`/`crit` 유지가 생각보다 느리면 이동 수가 줄어든다. P1에서 재고, 느리면 "급소 정보는 N번 이동마다 한 번 전체 재계산"으로 타협한다.
- 급소 최소화가 K 상승과 충돌할 수 있다(튼튼하게 만들수록 새 수를 위한 여유가 줄 수 있음). 그래서 사전식으로 K를 먼저 둔다. 가중치는 A/B로 정한다.
- 고득점 영역의 구조는 미측정이다(2.2 한계).

## 13. 열린 질문 (승인 전 확인)
- **Q1.** 고득점 영역(K≥6000)의 급소 비율·자유 칸 수를 지금 재 보면 "옛 SA가 7000에서 멈춘 이유" 가설을 바로 확인할 수 있다.
  옛 코퍼스/SA 격자를 **읽기 전용 측정에만** 써도 되나? (탐색 시드·학습 데이터로는 쓰지 않는다. 안 되면 우리 탐색이 거기 닿을 때까지 기다린다.)
- **Q2.** A/B(9장)는 팔 5개 × 시드 10개 × 30분 = 워커 7개로 **약 3.5시간**. 괜찮나?
- **Q3.** 급소 위험 F를 **손실 가중**(작은 수의 급소일수록 무겁게, 5장 기본)으로 할지 **단순 개수**로 할지?

- **Q5.** `T = 9999` 고정은 "1~9999를 전부 만든다(K≥9999)"를 목표로 삼는 셈이다. 현재 최고 기록이 7666이니 충분히 먼 목표지만,
  `K`가 9999를 넘으면 5자리 수도 체인에 넣어야 한다. **지금은 9999까지만 다루고, 넘으면 그때 확장**해도 되나?

## 14. 확정된 결정 (사용자 답변 누적)
- 실행 서버 1대만 사용. PyTorch 설치 허용. 결과는 서버에만 보관.
- 코퍼스·기존 SA 결과는 탐색·학습에 쓰지 않고 **완전 0부터**. 섬 10개 = 전부 0 출발 5 + 랜덤 5.
- ML은 "어느 숫자를 바꿔야 이득인가"로 표적 변경 (사용자). → 단일 변경은 정확 계산(M1), ML은 M4 첫 칸 선택에 쓴다 (7장).
- 핵심 목표: **급소(그 체인 하나 없애면 터지는 수) 최소화** (사용자).
- Q1 → 옛 코퍼스/SA 격자를 **읽기 전용 측정에만** 사용 허용 (시드·학습 금지).
- Q2 → A/B 약 3.5시간 서버 사용 허용.
- Q3 → 급소 위험은 **체인 수가 적은 수일수록 무겁게** (5장 `w(n)`).
- Q4 → ML은 고정 게이트 없이 **돌리며 직접 검증** (7장).
